autoSQL compiles a dashboard expression into SQL and runs it in Postgres. This demo puts that answer beside the answer today's Python gives, over the same rows, and marks every place they differ — because the failure this project exists to prevent is a silently wrong number, and the only way to catch one is to compute it twice.

The numbers no longer depend on a database setting

Postgres prints floating-point numbers to a precision a session variable controls. Set wrong, it returns numbers that are short — quietly. The shipping compiler is now immune to it.

compiling 1 / 3setting = 1setting = −3
the original prototype0.33333333333333330.333333333333
what ships today0.33333333333333330.3333333333333333
One thing this demo no longer shows, on purpose. Its centrepiece used to be a disagreement — the two engines returning different numbers. There isn't one any more: the last in-subset divergence was closed, so state 4 shows the exact value that used to come back wrong now reading 123 on both sides. That is the result, not a regression.
Every row in this demo is invented — fabricated by demo/seed/generate.py from fixed literal seeds. Nothing in it is real, and it never touches a live database. Full walkthrough in demo/WALKTHROUGH.md; the decisions behind it in kb/wiki/.
