# T-2 handoff — located and planned; the build has a contract, and four pieces of SQL that would not have run are fixed before anyone wrote them

**Where it is:** stage `locate`, **not blocked**. The `locate` and `plan` stages ran as one combo in
the `code-intel` seat on 2026-08-22 under the **full** process (`.autodev/shop.json →
settings.lean = false`, GA-6, wrap-up item 5). Pipeline so far: `intake → refine → design → queue →
locate (+plan)`. **Next stage: `build`**, in an isolated git worktree.

**Still nothing has been built.** There is no `demo/` directory, no seed script, no application. This
stage wrote **two documents and nothing else**.

> **Vocabulary, because this document uses shop jargon.** A **stage** is one step of work on a
> ticket. A **gate** is a checkpoint a ticket cannot pass until a named person signs it. A
> **go-ahead (GA-*n*)** is a recorded line from Evan authorising a class of decisions, logged
> verbatim with a timestamp in `.autodev/events.jsonl`. A **ruling on delegated authority** is a
> decision a session took *for* Evan under a go-ahead rather than one he made himself; each shows its
> derivation and each is overturned by one line from him. A **CTE** is a named sub-result written
> `WITH name AS (…)` in front of a SQL query, so the outer query can read it like a table.

## The risky part, first — the four punch-list items that described SQL which would not run

All four are resolved, and three of them were resolved by changing the *shape* of the statement
rather than by patching a line.

| # | what the spec implied | what Postgres does | **what runs instead** |
|---|---|---|---|
| **2** | the aggregate reads a previously-defined **alias** | **raises** `42703` — Postgres resolves SELECT-list aliases in `GROUP BY`/`ORDER BY`/`HAVING` and nowhere else | **B2:** the aggregate **re-emits the compiled expression inline**, which is what §7.2 item 5 already pinned. And under **B5a** a computed column is not even *emitted* when an aggregate is chosen, so the bug is removed by construction |
| **3** | operation 9 is a **filter**, emitted as a flag column | **raises** `42P20` — a window function cannot appear in `WHERE` | **B3:** the flag is computed in a **CTE** and filtered in the outer query. Written out in full, with six details pinned (why `changed` is never NULL, why the filter must be *inside* the CTE, why `LIMIT` must be *outside* it). AC-40(a) now counts real rows |
| **4** | operations 7, 8, 9 hard-code `ts` and `sender_id` | **runs, and is meaningless** — one partition, one NULL bucket, whole-record comparison, **identically on both panes, so the side-by-side agrees** | **B4:** restrict those three to `noun:Heartbeat` and grey them elsewhere with the collection's field list as the reason. This is **already the approved design** — part 3.1.2's rule X1, drawn in the mock Evan approved as drawn |
| **5** | any combination of operations is pickable | **raises** `42803` for every ungrouped column and `42P20` for a window in a grouped query | **B5a:** a pick has **exactly one of three shapes** — ROWS, SCALAR, BUCKET — and the shape decides every control. A full matrix, not two rules. Every illegal combination is **disabled with its reason stated** (DR-2), never refused after submit |

**And punch-list item 1**, which is adjacent and equally cheap to hit: two code fences both ending
`AS "bucket"` would give `ORDER BY "bucket" is ambiguous`. **B1:** one emitted column, the text label;
the `date_trunc(…)` is the inner expression and never carries an alias.

## Five things that would have stopped a builder cold, found while locating

None of these is in the punch list. They came from putting the file tree, the mock and this machine
side by side.

| | what is missing | resolved |
|---|---|---|
| **L1** | **18 of the mock's 30 icons do not exist in GIMS's sprite** — including `i-neq`, which is one of the five independent signals the disagreement banner relies on. Three more of the shared twelve have different path data | **B17** — two sprites, one resolver, the vendored file always wins |
| **L4** | **No Postgres driver and no FastAPI on this machine**, and PEP 668 blocks installing them — against AC-32's *"no network access beyond pulling the Postgres image"* | **B20** — a committed wheelhouse installed with `--no-index`, so offline is proven by the command rather than observed |
| **L5** | **No `psql` and no `pg_isready`** — the obvious readiness wait and the obvious bulk load both fail with *command not found*, and `up` would appear to hang | **B21** — readiness is a Python poll; the load uses the driver's `COPY` |
| **L8** | **`noun:EdgeCase` is specified as ten rows with "one purpose each" and only five purposes are named**, while AC-7 asserts exactly ten | **B24** — all ten named, each with a `label` key, plus two constraints (no EdgeCase row may carry `status`, or AC-45(a) breaks) |
| **L11** | **A bucketed pick with no aggregate is undefined** | **B5c** — switching on the bucket sets the aggregate to `count`, visibly, which is what walkthrough step 7 already assumes |

The other six (a token fork hazard in the mock, `.gitignore` swallowing the committed bundles, no
browser automation for five "a UI test asserts…" criteria, `./run-demo test` never saying whether it
starts the stack, how many rows the panes render, and an acceptance criterion that is literally
unsatisfiable as written) are in locate §7 with their resolutions.

## Two places the build will exceed the drawing Evan approved

"Approved as drawn" is a real commitment, so both are named here rather than discovered at `accept`.
Each is one line to overturn.

1. **The bucketed view greys one more control than the mock does.** The mock's `V2` draws two
   operations disabled (the two the design brief's rule X2 names). **B5a** disables three — operation
   9 as well, because a window function's `PARTITION BY` over ungrouped `data` raises `42803`. The
   brief derives X1 and X2 from the spec and never claims the pair is exhaustive; the punch list
   exists because the spec names none. *Overturn:* **"Leave operation 9 available on a bucketed
   pick"** — which really means "go back to refusing after submit".
2. **The invented-data label appears in three places, not two.** The mock puts an amber chip and a
   banner in the header. **B31** adds one small `invented` chip to **each answer pane's head**,
   because a screenshot of the answer panes alone — which is exactly what gets pasted into a message
   to an employer (Q43) — carries neither of the header's two. *Overturn:* **"The header chip is
   enough."**

**Two things the plan pins that the spec never said at all**, and a builder would have had to invent:
the filter's boolean bridge is **`xpr.truthy(<compiled expression>)`** (verified: `runtime.sql:61-75`

merging, because `compile.py` restarts its bind parameters at `p0` on every call (verified:
`compile.py:159-164`, `:437`) — three fragments in one statement would otherwise overwrite each
other's values and produce a wrong number that runs clean.

## The test approach, in one paragraph, because it is the point

This project's failure mode is *a subtly wrong number that still runs clean*. §8 of the plan answers
five ways a wrong number could survive and names what fires for each: **absolute assertions on each
pane separately before the panes are compared** (the only defence against both panes being wrong the
same way); **three independent producers** of every walkthrough number, with an AST test forbidding
the expectations file from importing either of the other two; **no tolerance anywhere**, enforced by
a grep, because a tolerance is exactly how the defect this demo exists to show would be hidden;
**assertions chosen to fail by an order of magnitude** (operation 9's band is 700–1,100 against a
wrong answer of 8,400); and **ten-run repeats** so an order that is stable by luck of the plan fails.
On top of those, a **mutation pass**: sixteen one-line defects, each naming the criterion that must
fail, run before handover. That exists because of this repository's own precedent — T-1's re-check
found every failure-reporting branch of its conformance harness had **0 executions** across a full
run. Those branches were dead, not broken, and nobody could have told from a green suite.
