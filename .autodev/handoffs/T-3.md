## What the run is

> On the **restricted 32-construct subset only**, with the known guard defect fixed first, does the
> SQL autoSQL generates ever disagree with GIMS's Python evaluator — a different value, a value
> becoming null, a null becoming a value, or Python raising where SQL quietly returns a number — at
> **any** of Postgres's three `extra_float_digits` settings?

One sentence, and it is the whole ticket. The subset is 32 of the expression language's 48
constructs, covering 68 of the 130 contract test cases; its functions are exactly seven —
`abs coalesce count if length max min`. Dates, strings, `sum`, `avg`, `round`, `floor`, `ceil` and
`%` are all outside it. `extra_float_digits` is a Postgres session setting controlling how many
digits a float prints as; it is **not** cosmetic here, because it changes what `to_jsonb(float8)`
itself returns — so it sits on the value channel, not the display channel. Evan's Q10 requires all
three settings (`1`, `0`, `-3`), each reported separately.

**Full spec:** `spikes/T-1/EXPERIMENTS.md` §1. **The bar and everything below:**
`spikes/T-3/FRAMING.md` (751 lines after the 2026-08-22 refresh). Where the two differ, EXPERIMENTS.md §1 is the specification and
the framing is the bar.

## The pass bar

**Zero wrong answers of any kind, at each of `extra_float_digits` = 1, 0 and −3, reported
separately.** Not "few". Not "none we could reach". Zero.

| # | wrong-answer class | count required, per setting |
|---|---|---|
| 1 | **different value** — both sides returned a value and they differ | **0** |
| 2 | **value → null** — Python returned a value, SQL returned null | **0** |
| 3 | **null → value** — Python returned null, SQL returned a value | **0** |
| 4 | **Python raised, SQL returned a value** (`PY_RAISE` in `differ.py`) | **0** |

**A pooled figure across the three settings is forbidden** — it would hide which setting broke, which
is the entire reason Q10 exists. **Class 4 is the one the existing instruments cannot see:**
`differ.py` buckets `PY_RAISE` away from `DIVERGE`, so today a run can print "zero divergences" while
Postgres confidently answers questions Python refuses to answer at all.

**The subset fails this bar today, and that is the starting position, not a surprise.** Twenty
expression paths driven against a record holding `a = 1e300` — an ordinary finite double — produce
**16 divergences, 8 of them entirely inside the subset**, including one *wrong number* rather than a
null (`max($.l)` → `1`). The cause is one mistyped literal: the JSON-to-`float8` guard in
`proto/runtime.sql` is written out as a full integer and is **12 digits short**, at **two** sites
(`runtime.sql:33` in `xpr.f8` and `:51` in `xpr.num`) — **24 characters in total**, not the "twelve
characters" EXPERIMENTS.md §1.2 calls it, because that figure counts one site. **Step zero of the run
is fixing those 24 characters** (Q7 permits editing the instruments in place) and re-running the
twenty paths as a before-and-after. If the eight in-subset divergences do not all go to zero, the
cause is not the literal, and that is a bigger finding than anything else this run could produce —
stop and characterise it.

## The negative control — required, and required BEFORE any result is quoted

**No real number may be quoted, in any document, until this has passed.** A control run afterwards is
a control that already knows the answer it needs.

**This project has already made exactly this mistake once.** A full normal run of
`proto/conformance.py` under a line tracer showed `DID_NOT_COMPILE` hits=0, `SQL_ERROR` hits=0,
`COMPILED_DIVERGES` hits=0, `COMPILED_AGREES` hits=130 — **three of the four failure branches had
never executed.** Every conformance headline in the record came from a rig whose failure branches
were dead surface, and it stayed that way until Evan asked for the check himself (Q4). When it was
finally driven, the branches worked — **dead, not broken** — but nobody knew that, and nobody could
have.

**And the instrument that was tested is not the instrument that matters.** Only `conformance.py` was
covered. `differ.py` — *"the instrument that produced every decision-relevant divergence"* — has
never been shown able to fail, and **`differ.py` is where T-3's entire headline comes from.**

So, binding:

- Deliberately wrong compilations are pushed through the **real** path, each declaring in advance
  which class it must land in. `spikes/T-1/proto/conformance_injection_test.py` is a working
  template — it swaps the compiler handle and asserts on the emitted outcome string without
  modifying the harness.
- Minimum coverage: one each of **class 1** (different value), **class 2** (value → null), **class 3**
  (null → value), **class 4** (`PY_RAISE`), a **named refusal**, and an **unexplained raise**.
- **If any injection is scored as agreement, the run refuses to report anything.** Not a caveat in
  the write-up. No output.
- **Run it once per `extra_float_digits` setting, not once overall** — it doubles as proof that the
  new setting-switching code is live on that path.

**A positive control is required too, for the same reason.** `differ.py:79` hard-codes
`SET extra_float_digits = 1` — a second pin that EXPERIMENTS.md §1.4's work list does not mention. If
the new switching code silently fails, all three runs execute at setting 1 and print three identical
passes that look exactly like Q10 being satisfied. So per setting: read the value back with
`select current_setting('extra_float_digits')`, record it beside the input fingerprints, and show a
value that actually differs (e.g. `1/3` printing 16, 15 and 12 significant digits). **Two settings
that print identically is a failed control, not a finding.**

## The risky part, for the next seat

> **T-3's headline is a count of zeros coming out of `differ.py` — and `differ.py` has never been
> shown able to print anything but a zero.**

Every ingredient of a false green light is already on disk: an instrument with untested failure
paths, a language whose Python side is *total* (it never throws — it returns `null`), a bar whose
passing value is the same character an empty result prints, and a project whose one previous rig
turned out to have three dead failure branches nobody noticed until Evan asked.

Build so that **five outcomes stay visibly distinct end to end** — agrees · diverges (with its class)
· named refusal · unexplained raise · did-not-compile — never four, and never a pass column plus an
everything-else column. Then break it on purpose, in each of the five, before quoting a single real
number.
