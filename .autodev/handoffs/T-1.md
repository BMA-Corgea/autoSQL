## The risky part, first

**1. The test rig can report a failure — and that takes an argument *away* from the NO-GO.**
The rig runs each of the 130 test expressions twice, once through GIMS's Python evaluator and once
through Postgres, and compares the two answers. The worry was that it had never once been seen to say
*fail*, so "130 of 130 agree" might have meant "the rig cannot say no". Measured with a line tracer:
every branch that reports a failure had run **zero** times. Then it was fed six deliberately wrong
compilations, and it reported all six correctly — including the important one, where the compiler
refuses to compile at all: that case landed in the **denominator**, the rig printing
`Pass rate = 125/130 = 96.2%` instead of quietly scoring 130/130 again. **The branches were dead, not
broken.** So 130 of 130 is a real result. The consequence for the ruling: `FINDINGS.md` books the
"the test file isn't good enough" leg as *firmer* **because** those branches had never fired — that
ground is now spent, and the page has been corrected to say so. The leg falls back on its other
argument (the restricted subset covers only 68 of the 130 cases, 52.3%), which was always the stronger
half and which re-derived exactly. Read the right way, **130/130 got stronger; the NO-GO did not get
weaker**, because 130/130 was never what it rested on.

## What the ruling rests on

Three facts, and the re-check touched none of them:

1. **There is nowhere in GIMS to report a fallback.** `resolve()` in
   `GIMS-Project/api/dashboard/sources.py:357` returns `{records, count, truncated}` and nothing else.
   The spike's own non-negotiable — a fallback to in-memory evaluation must be *reported, never
   silent* — cannot be met without changing that contract and the frontend that reads it. Your Q3
   answer allows that change, **after the demo**.
2. **The compiled path is 3.79× to 7.15× slower** across six table sizes, with no crossover and the
   gap widening as the table grows. Re-derived exactly in this pass. **Your Q11 answer makes this
   harder, not softer:** with index use permanently off, every generated query must read the whole
   table, which is the one route by which the compiled path could ever have got faster. That number
   is now a floor.
3. **18 of the 33 ways the two engines can disagree cannot be detected at query time by any
   mechanism** — not by a rule, not by a test, not at runtime. Re-derived exactly in this pass.

The one outcome that would have overturned the ruling — the rig scoring "did not compile" as a pass,
which would void every conformance number underneath it — is exactly the outcome this pass did not
get.
