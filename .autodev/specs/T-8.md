# T-8 — Adopt variant C as the shipping runtime, with a regenerable digit mapping

**Spawned by:** T-6 (`links.intent=T-6`) · **Ruling it implements:**
`kb/wiki/decision-t6-correctness-rerun.md` · **Written:** 2026-09-01 ·
**Authority:** GA-12 (*"accept T-2 and keep going with T-8"*) · **Pipeline:** `feature@v1` ·
**Lean: OFF; risk HIGH vetoes lean regardless**

## 1. What this is

T-6 measured three ways of handling the Unicode-digit coercion gap and ruled **variant C**: after the
plain-ASCII numeric gate fails, strip Python's full 29-code-point whitespace set and map the 670
non-ASCII decimal-digit code points onto `0`–`9`, then re-test. SQL then **agrees with Python**
outright rather than refusing.

**Measured, not asserted** (T-6 `FINDINGS.md` + addendum): 0 wrong numbers at the pinned float
setting across 11,367 expressions in three batteries; contract fixture 130/130; **0 refusals**, where
the ruled alternative raised 86 — of which 60 replaced answers that were already correct; **812 ms
against an 852 ms baseline** per 300k ordinary coercions, i.e. no measurable cost.

This ticket puts that runtime somewhere a product can ship from, and makes its digit mapping
**regenerable** instead of a frozen literal.

## 2. The constraint that shapes everything: two files must not be edited

**`spikes/T-1/proto/runtime.sql` is evidence, not source.** Its sha256 `1c58d548a6045aa6…` is cited
as a fingerprint in T-3's findings, T-6's attestation, and every one of T-6's 42 battery outputs.
Editing it would break the chain that lets anyone re-derive those results. **It stays byte-identical,
forever.**

**`spikes/T-6/runtime*.sql` are likewise a spike's recorded artifacts.** They are the *provenance* of
this change, not its home.

**Consequence: autoSQL has no shipping home for its runtime, and this ticket creates one.** The
project is greenfield — there is no `src/`, and the only two copies of `runtime.sql` on disk are a
spike prototype and a vendored copy inside the demo. That is fine for a spike and wrong for a
product.

## 3. Scope

### 3.1 Create the runtime's canonical home — `runtime/`

| file | what it is |
|---|---|
| `runtime/runtime.sql` | **GENERATED.** The shipping runtime: T-1's proto plus variant C's coercion branch. Not hand-edited. |
| `runtime/generate.py` | The generator. Reads `runtime/runtime.sql.in`, derives the digit and whitespace tables from the **running Python's** `unicodedata`, and writes `runtime/runtime.sql`. |
| `runtime/runtime.sql.in` | The template — the hand-written source, with `{{ND_MAP_FROM}}`, `{{ND_MAP_TO}}` and `{{PY_WS}}` placeholders. |
| `runtime/README.md` | Where this came from, why the spike copies are frozen, and how to regenerate. |

### 3.2 The mapping must be regenerable, and drift must fail loudly

The 670-code-point table is derived from `unicodedata`, so **a Python version whose Unicode data
moves silently splits the two engines** — Python would coerce a digit the SQL mapping has never heard
of, and the divergence class T-6 just closed reopens without a single line of code changing.

- `runtime/generate.py` is the only writer of `runtime/runtime.sql`.
- A test asserts the **committed** `runtime/runtime.sql` is byte-identical to what the generator
  produces **on the running interpreter**. It fails on drift, naming the code points that moved.
- A second test asserts the installed mapping covers exactly the set Python's `float()` accepts —
  the same 0-false-negative / 0-false-positive check T-6's `P0` ran, kept as a standing test rather
  than a one-off probe.

### 3.3 Re-vendor into the demo, and keep the demo green

`demo/vendor/runtime.sql` becomes a byte-identical copy of `runtime/runtime.sql`, its
`demo/manifest.json` digest updated, and `demo/vendor/NOTICE.md` corrected — it currently describes
everything under `vendor/` as copied from a GIMS checkout, which has never been true of
`runtime.sql`. That is a **documentation defect this ticket fixes in passing**, and it is named here
so the fix is not mistaken for scope creep.

### 3.4 Step 11 of the demo — the thing that is not a bug

**Adopting variant C removes the demo's centrepiece disagreement.** `$.m` (`["１２３", 1]`) stops
diverging exactly the way `$.l` did before it, because the two engines now agree. That is **T-6
passing**, not a regression.

On present evidence **no in-subset value disagreement survives this change**, so step 11 cannot keep
claiming *"the two engines disagree"*. It becomes **the magnitude refusal** — `edge-03`'s `1e400`,
already demonstrated at step 13 — and the claim becomes *"the tool refuses rather than guessing"*.

## 5. Acceptance criteria

- **AC-1** — `runtime/runtime.sql` exists, is generated, and installs into a clean Postgres 16 with
  **21 functions in schema `xpr`**. *Test:* install into a throwaway container and count.
- **AC-2** — `xpr.num` **agrees with Python's `_to_num`** on every case in T-6's 52-case predicate
  set, with **zero refusals of the coercion class** and the magnitude refusals (`XPR01`) intact.
  *Test:* T-6's `P1` promoted from a probe to a standing test.
- **AC-3** — The committed `runtime/runtime.sql` is **byte-identical** to the generator's output on
  the running interpreter. *Test:* regenerate to a temp file and compare.
- **AC-4** — The digit mapping covers **exactly** the non-ASCII code points Python's `float()`
  accepts: 0 false negatives, 0 false positives. *Test:* enumerate against `unicodedata`.
- **AC-5** — The ASCII path costs no more than it did. *Test:* the guarded `translate()` is **inside**
  the failure branch — asserted structurally, so the nesting cannot be "tidied" away — plus a timing
  check that the ASCII path stays within 1.5× of the ungenerated baseline.
- **AC-6** — `demo/vendor/runtime.sql` is byte-identical to `runtime/runtime.sql`, the manifest
  digest matches, and `NOTICE.md` states its true provenance. *Test:* the existing vendor drift test,
  extended.
- **AC-7** — **The demo suite is green**, with step 11 re-pointed to the magnitude refusal and its
  own tests asserting *that* outcome rather than a divergence. *Test:* `./run-demo test`.
- **AC-8** — **T-1's and T-6's spike runtimes are byte-identical to their recorded digests.**
  *Test:* sha256 comparison against the values quoted in §2.

## 6. What would make this unacceptable

- Editing `spikes/T-1/proto/runtime.sql` or any `spikes/T-6/runtime*.sql`.
- Hand-editing `runtime/runtime.sql` instead of the template.
- Hoisting `translate()` above the ASCII gate (T-6 measured that at 5.3× on the common path).
- Leaving the demo suite red, or making it green by weakening an assertion rather than re-pointing
  it at the outcome that now happens.
- Touching port 55433, or anything in either GIMS checkout.
